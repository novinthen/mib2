# MIB 2.0 Service Commitment Standard

**Control status:** Internal design standard for agency validation. No commitment is represented as adopted, and no numeric case-processing deadline is implied.

These commitments define the minimum household-visible administrative experience that the programme architecture is designed to deliver. Each row is generated from `SERVICE_COMMITMENT_REGISTER.csv`.

## SC-01 — Named case ownership

**Adoption status:** `draft_pending_agency_confirmation` · **Timeline status:** `pending_agency_capacity_confirmation`

| Control field | Controlled position |
|---|---|
| Service commitment | Every accepted individual, household or enterprise case receives a named case owner or named responsible service unit, with a recorded handover when responsibility changes. |
| Applicability | Applies to programmes that accept an identifiable beneficiary, applicant, household or enterprise into case-managed or navigation support. |
| Programmes | PRG-01;PRG-02;PRG-05;PRG-06;PRG-07;PRG-08;PRG-09;PRG-10;PRG-11;PRG-12;PRG-13;PRG-14 |
| Implementation point | Assignment is recorded when the case is accepted into the participating service; transfer is recorded when ownership changes. |
| Timeline boundary | No numeric assignment deadline is set. Each responsible agency must agree the assignment point and any elapsed-time standard after workflow and caseload validation. |
| Capacity evidence required | Opening caseload; staff and provider capacity; case-to-owner ratio; operating hours; system capability; handover and absence coverage. |
| Standard owner | Accounting officer for each affected programme |
| Performance measure | Accepted cases with a recorded current owner or responsible unit; unowned cases; ownership transfers lacking a recorded handover. |
| Reporting frequency | quarterly |
| Escalation and remedy | An accepted case without a recorded owner is an operational exception routed to the programme service manager and then through the published complaint and escalation route. |
| Excluded outcomes | Does not guarantee citizenship, documentation status, admission, employment, procurement, housing, financing or investment outcomes; the owner manages process and referral only. |
| Required acceptance | Written evidence: not received. Acceptance date: not recorded. |

## SC-02 — Acknowledgement and status visibility

**Adoption status:** `draft_pending_agency_confirmation` · **Timeline status:** `pending_agency_capacity_confirmation`

| Control field | Controlled position |
|---|---|
| Service commitment | Every validly lodged application or service request receives an acknowledgement, a traceable reference and access to its current procedural status through an approved channel. |
| Applicability | Applies to programmes that receive an application, referral, enrolment request or other traceable service request from an identifiable person, household or enterprise. |
| Programmes | PRG-01;PRG-02;PRG-05;PRG-06;PRG-07;PRG-08;PRG-09;PRG-10;PRG-11;PRG-12;PRG-13;PRG-14 |
| Implementation point | Acknowledgement follows valid lodgement; status visibility continues until transfer, decision, closure or withdrawal. |
| Timeline boundary | No acknowledgement or update deadline is set. Agencies must validate channel capacity, system integration and update events before adopting elapsed-time standards. |
| Capacity evidence required | Application volumes; workflow and channel capacity; system interfaces; assisted-access requirements; identity verification; status taxonomy; staffing and failure recovery. |
| Standard owner | Accounting officer for each affected programme |
| Performance measure | Validly lodged requests with acknowledgement and reference; requests with accessible current status; status records not updated after a defined process event. |
| Reporting frequency | quarterly |
| Escalation and remedy | Missing acknowledgement or inaccessible status may be challenged through assisted channels and the programme complaint route without affecting the merits of the underlying decision. |
| Excluded outcomes | Status visibility does not create entitlement, disclose protected deliberations or override the competent decision-maker. |
| Required acceptance | Written evidence: not received. Acceptance date: not recorded. |

## SC-03 — Written reasons or referral record

**Adoption status:** `draft_pending_agency_confirmation` · **Timeline status:** `pending_agency_capacity_confirmation`

| Control field | Controlled position |
|---|---|
| Service commitment | Every decision, non-acceptance, closure or onward referral provides a written reason or reason category, identifies the responsible decision route and states the available review, correction or complaint channel, subject to lawful disclosure limits. |
| Applicability | Applies where a participating programme decides process eligibility, closes a service case or refers a matter to another competent body. |
| Programmes | PRG-01;PRG-02;PRG-05;PRG-06;PRG-07;PRG-08;PRG-09;PRG-10;PRG-11;PRG-12;PRG-13;PRG-14 |
| Implementation point | The record is issued with the relevant decision, closure or referral, using legally cleared templates and disclosure rules. |
| Timeline boundary | No separate day-count is set. Agencies must agree the permissible reasons taxonomy, template and any follow-up standard after legal and workflow review. |
| Capacity evidence required | Legal disclosure matrix; decision and referral taxonomy; template testing; language and accessibility needs; review-channel capacity; protected-record controls. |
| Standard owner | Accounting officer for each affected programme with legal clearance from the competent authority |
| Performance measure | Decisions, closures and referrals carrying an approved reason or reason category and an identified review, correction or complaint channel. |
| Reporting frequency | quarterly |
| Escalation and remedy | An absent or unintelligible process reason may be challenged through the published correction or complaint route; merits review remains with the legally competent body. |
| Excluded outcomes | Does not require disclosure prohibited by law, fetter discretion or promise reversal on review. |
| Required acceptance | Written evidence: not received. Acceptance date: not recorded. |

## SC-04 — No-wrong-door referral

**Adoption status:** `draft_pending_agency_confirmation` · **Timeline status:** `pending_agency_capacity_confirmation`

| Control field | Controlled position |
|---|---|
| Service commitment | A person who approaches a participating programme with an in-scope need is either assisted by that programme or transferred through a documented referral to the competent participating body, with consent where personal data is shared. |
| Applicability | Applies to multi-agency access, navigation and case-management services where the first contact may not control the requested service. |
| Programmes | PRG-01;PRG-02;PRG-05;PRG-06;PRG-07;PRG-08;PRG-09;PRG-10;PRG-11;PRG-12;PRG-13;PRG-14 |
| Implementation point | Referral responsibility is recorded at triage and remains visible until the receiving body accepts, rejects or redirects the referral under the agreed protocol. |
| Timeline boundary | No transfer or acceptance deadline is set. Participating agencies must approve referral protocols, capacity limits and escalation points before numeric standards are adopted. |
| Capacity evidence required | Agency directory; signed referral protocols; receiving capacity; consent and data-sharing controls; rejection and bounce-back codes; assisted and offline channels. |
| Standard owner | Chief Secretary coordination mechanism and accounting officers for affected programmes |
| Performance measure | In-scope contacts assisted or referred; referrals accepted by the receiving body; repeated referrals; referrals lacking recorded consent where required. |
| Reporting frequency | quarterly |
| Escalation and remedy | Rejected, stalled or repeatedly redirected referrals enter the named inter-agency escalation route; the originating service remains responsible for explaining the next process step. |
| Excluded outcomes | Does not compel another agency to approve the underlying application or accept a referral beyond its lawful mandate and verified capacity. |
| Required acceptance | Written evidence: not received. Acceptance date: not recorded. |

## SC-05 — Published eligibility and queue rules

**Adoption status:** `draft_pending_agency_confirmation` · **Timeline status:** `pending_agency_capacity_confirmation`

| Control field | Controlled position |
|---|---|
| Service commitment | Before intake or selection opens, each participating programme publishes its eligibility, required evidence, prioritisation method, capacity limit, waiting-list or queue rule, material exclusions and review or correction route in accessible form. |
| Applicability | Applies to all beneficiary-facing, institution-facing or applicant-facing programmes that ration access, sequence works or select participants. |
| Programmes | PRG-01;PRG-02;PRG-03;PRG-04;PRG-05;PRG-06;PRG-07;PRG-08;PRG-09;PRG-10;PRG-11;PRG-12;PRG-13;PRG-14 |
| Implementation point | Publication and accessibility testing occur before the relevant intake, selection round, works prioritisation or waiting list becomes operative. |
| Timeline boundary | The pre-opening publication event is fixed, but no processing or waiting-time limit is set until agencies validate demand, capacity and queue behaviour. |
| Capacity evidence required | Verified eligibility authority; demand and capacity model; prioritisation method; queue design; accessibility and language testing; correction and change-control process. |
| Standard owner | Accounting officer for each affected programme |
| Performance measure | Programmes publishing the complete rule set before opening; material rule changes versioned and notified; cases processed under unpublished or superseded rules. |
| Reporting frequency | quarterly |
| Escalation and remedy | A material unpublished rule or unannounced change triggers intake review, applicant notification and correction under the programme escalation route. |
| Excluded outcomes | Publication does not convert capacity-limited assistance into a universal entitlement or displace statutory criteria. |
| Required acceptance | Written evidence: not received. Acceptance date: not recorded. |

## SC-06 — Quarterly service-performance reporting

**Adoption status:** `draft_pending_agency_confirmation` · **Timeline status:** `pending_agency_capacity_confirmation`

| Control field | Controlled position |
|---|---|
| Service commitment | Service-performance results are reported quarterly using aggregate, auditable measures that show demand, access, acknowledgement, ownership, status, referrals, reasons, queues, complaints and unresolved exceptions where applicable. |
| Applicability | Applies across the full portfolio; PRG-15 governs escalation and PRG-16 governs data quality, disclosure control and public reporting. |
| Programmes | PRG-01;PRG-02;PRG-03;PRG-04;PRG-05;PRG-06;PRG-07;PRG-08;PRG-09;PRG-10;PRG-11;PRG-12;PRG-13;PRG-14;PRG-15;PRG-16 |
| Implementation point | Each completed quarter produces a controlled management report; public release follows approved data-quality, small-cell, privacy and disclosure rules. |
| Timeline boundary | Quarterly cadence is proposed. Cut-off, assurance and publication dates remain unset until PRG-15 and PRG-16 capacity and reporting controls are accepted. |
| Capacity evidence required | Common data definitions; reporting calendar; data-owner certification; quality thresholds; disclosure control; dashboard capacity; correction and restatement process. |
| Standard owner | Chief Secretary to the Government through PRG-15 and PRG-16 owners |
| Performance measure | Quarterly completeness and timeliness; programme coverage; unresolved data-quality exceptions; restatements; service-standard exceptions by applicable commitment. |
| Reporting frequency | quarterly |
| Escalation and remedy | Missing, late or materially unreliable returns are recorded as delivery exceptions and escalated through PRG-15; unsafe or unverified public data are withheld under PRG-16 controls. |
| Excluded outcomes | Reporting does not prove causation, disclose protected personal information or imply that an administrative output guarantees a substantive outcome. |
| Required acceptance | Written evidence: not received. Acceptance date: not recorded. |

## SC-07 — Defined escalation and complaint route

**Adoption status:** `draft_pending_agency_confirmation` · **Timeline status:** `pending_agency_capacity_confirmation`

| Control field | Controlled position |
|---|---|
| Service commitment | Every participating service publishes a usable route for correction, complaint and escalation; unresolved matters have a named next-level owner, and complainants can track closure or onward referral. |
| Applicability | Applies to beneficiary services, institutional programmes, governance reporting and data-publication functions, with merits appeals remaining in existing lawful channels. |
| Programmes | PRG-01;PRG-02;PRG-03;PRG-04;PRG-05;PRG-06;PRG-07;PRG-08;PRG-09;PRG-10;PRG-11;PRG-12;PRG-13;PRG-14;PRG-15;PRG-16 |
| Implementation point | The route is published before programme launch or function activation and is used whenever first-line correction does not resolve the recorded issue. |
| Timeline boundary | No complaint-resolution deadline is set. Agencies must validate complaint volumes, severity triage, independence, staffing and existing statutory review routes before elapsed-time standards are adopted. |
| Capacity evidence required | Complaint taxonomy and baseline; first- and second-line capacity; protected disclosure route; independence and conflict controls; statutory appeal map; tracking and closure evidence. |
| Standard owner | Accounting officer for each programme with PRG-15 portfolio escalation |
| Performance measure | Complaints acknowledged and traceable; first-line corrections; escalations by category; closures with recorded outcome; unresolved exceptions and repeat complaints. |
| Reporting frequency | quarterly |
| Escalation and remedy | Unresolved process complaints progress to the named next-level owner and then the applicable independent, statutory or portfolio route; urgent safety, safeguarding, integrity and data-breach matters follow existing emergency channels. |
| Excluded outcomes | Does not replace judicial review, statutory appeals, procurement challenges, labour processes or other legally competent remedies, and does not guarantee the substantive result sought. |
| Required acceptance | Written evidence: not received. Acceptance date: not recorded. |
